# 默认分类、行程与家庭共同记账需求

确认日期：2026-10-31（北京时间）。状态：主要功能已实现，SQLite 自动测试与隔离 Web 验收通过；真实双 iPhone／WebDAV 与安装升级仍待验收。

本文整理本轮用户讨论结果，作为后续开发与验收依据。默认分类取代原始 v0.3 规划 §11.2 的示例；其他未涉及的现有能力继续遵循项目约定。原始规划保留，不回写。现有实现与本文有差异时，按本文安排后续改造。

## 1. 目标与范围

- 一个家庭账本同时记录夫妻双方消费，支持互相代记，无需为旅行另建账本。
- 分类回答“钱花在什么上”；行程回答“这次旅行总共花了多少”；付款人回答“谁实际付款”；记录人回答“谁录入账单”。这些维度可以组合，不复制流水。
- 单独统计四轮汽车每年实际使用费，购车支出单列；两轮电动车归交通。
- 保留常用分类入口，让细分类不增加日常记账步骤。
- 需求整理后已按用户授权开始实现；实现记录、验收范围和实际入口见第 9 节。

| 场景 | 归属与规则 |

| 酒店、民宿、景区乐园展览门票 | 娱乐／住宿或门票；旅行与非旅行都可使用 |

| 明确做东、替亲友承担的聚餐费用 | 人情往来／请客；不与娱乐／聚餐重复记账 |
| 宠物洗护、寄养等 | 宠物／服务；没有发生的子类允许隐藏 |
| 转账手续费等实际收费 | 其他／手续费 |

“大额支出”沿用已确认名称，表示重要物品的一次性购置，不设置“超过某金额就迁入”的自动规则。贷款购车沿用现有本金与费用口径，不重复记录全额购车支出和分期本金；贷款本金不默认计入日常用车费。

### 2.3 收入与账务操作

默认收入为独立一级分类，不强制二级分类：工资奖金、副业收入、福利补贴、公积金、红包礼金、二手出售、其他收入。

- 公积金明确保留，不合并到工资或其他收入；本文不推断其历史记录是缴存还是提取，也不自动重分类。
- 取消“意外收入”默认入口，以其他收入兜底；不根据历史随手选择的分类推断真实收入来源。
- 退款、内部转账、还款、余额调整沿用账务操作类型，不做普通收支默认分类。
- 夫妻之间转钱、红包，在家庭口径下为内部转账；购物或消费发生时才形成消费，不重复计算。
- 原规划将报销列为本期不做，本轮不增加报销功能。
- 公司饭卡目前由用户不记录。本轮不自动新增餐补收入、饭卡账户或虚拟食堂消费；是否完整记录饭卡留待实际使用时另行决定。

### 2.4 默认值与历史分类升级

- 新账本使用本表初始化；已有账本仅在一级分类完整且仍按上一版默认顺序排列时一次性升级顺序，不改账单、分类 ID、隐藏状态或常用项；自定义名称及排序保持原样。
- 已有账本通过显式的分类整理预览应用新方案，复用现有迁移能力：先列出旧分类、新去向及影响范围，再执行；模糊分类允许逐笔处理或暂时保留。
- 不因分类调整重写真实消费金额、付款账户或账户余额，不自动丢弃历史记录。
- 历史“礼物”是否都属于伴侣礼物需用户核对后迁到宠你；历史收入不自动纠正。
- 旧通勤不能直接推断为打车或地铁；旧购物、日用可能混合多种用途；旧大件有搬家费，不能整类无条件映射为数码或家电。
- 旧娱乐／旅行不能直接改成住宿；需要逐笔拆明用途，或暂留历史分类。新行程不按日期自动吞入旧账。
- 常用项关联随显式迁移更新，已被后来修改的常用项不强行覆盖；继续符合现有分类删除与恢复的余额不变约定。
- 保持默认数据初始化与升级幂等，重复启动、重试迁移或同步不生成重复分类。

## 3. 行程功能

### 3.1 用户流程

1. 在家庭账本或记账页的行程面板直接创建行程，例如“杭州周末游”，填写名称，用日期选择器选择可选起止日期。
2. 行程管理页可手动设为本机“当前行程”；记账页“创建并关联”同时设为本机当前行程。记账时自动带上关联，明显展示行程名称，单笔可一键取消或改选。
3. 提前订酒店、买票以及回来后补记，都可手动关联；行程日期不限制消费日期。
4. 结束行程后停止自动关联。历史账单、汇总和补记入口保留，已结束行程仍可编辑。
5. 打开行程查看家庭总花费、双方付款金额、分类汇总和逐笔明细，并可导出行程账单。

### 3.2 分类、行程与总额

- 行程是同一本家庭账本中的结构化标签，一期一笔流水最多关联一个行程；不要求先实现任意多标签系统。
- 取消新账默认的娱乐／旅行子类，增加娱乐／住宿；聚餐、门票继续留在娱乐。汽车、交通、餐饮等按正常分类记。
- 一笔汽车过路费关联行程后，同时出现在年度汽车统计和该行程汇总，但底层只有一笔消费、一次账户影响；家庭总支出只计一次。
- 行程总花费为关联消费抵减相应退款后的金额；不把家庭转账、还款本金、余额调整作为旅行消费。退款沿用现有超额转收入规则，超额收入不再抵减消费。
- 退款必须继承或按原消费关联行程，统计中不得同时抵减原账退款字段与退款流水。修改原账行程后，相关退款口径保持一致。
- 行程汇总按所选范围内的已记录数据计算，不推算遗漏账单。双方已记录的消费一起纳入；付款人分项之和与总额可核对。
- 行程总额按实际消费汇总；记录人或为谁筛选不能被暗中当作付款人筛选。
- 删除／移除行程关联不删除消费、不改变余额。行程本身删除前提示关联账单数量，移除关联后保留全部账单；允许直接结束行程长期留存。

### 3.3 双人同步与导出

- 行程名称、日期、结束状态及账单关联是家庭共享数据，双方可查看和维护，离线可记录，恢复联网后同步。
- “本机当前行程”属于本机偏好，不能因一方开启而自动开启另一台手机；另一方可自行选中同一行程。
- 共享行程结束状态同步到设备后，不再自动关联；离线期间已有的关联消费保留，单笔可修正。打开结束状态未知时不承诺跨设备即时停止。
- 行程明细、正常明细和导出可见行程名称、付款人、付款账户、记录人；行程导出支持 Excel／CSV，包含分类、消费时间、备注、退款和净消费等核对字段。
- 一期不增加旅行拆账、AA 结算、预算或行程攻略。

## 4. 家庭共同记账与代记

### 4.1 字段含义

| 信息 | 含义与默认行为 |
| --- | --- |
| 付款人 | 根据所选账户的所属成员自动确定；记账页不再展示独立选择控件 |
| 付款账户 | 实际扣款的家庭可见账户，可选自己的及另一半已共享的可用账户 |
| 记录人 | 首次创建账单的实际操作者，自动保存，不要求用户填写 |
| 为谁 | 保留历史数据兼容，记账页不再展示；新账沿用共同默认值 |

- 成员以稳定 ID 存储，跨设备通过成员身份显示“我／另一半”或名称，不能把本机相对的“我”当成固定归属。
- 新账无账户所属成员时默认记录者；不凭空新增第三个家庭成员。
- 新账及修改付款账户时，付款人随账户归属变化；仅修改原账其他内容时保留原付款人（包括未确认），不改写历史归属。
- 示例：老婆付款、老婆的微信、你代记。同步后她查看的是同一条账，可修改分类、备注或行程，无需确认生成第二条账。
- 编辑原账不改写首次记录人；若展示最近修改人，应另行保存，与记录人区分。
- 收入、转账等操作使用适合其含义的字段名称；不把所有流水都硬标成消费付款。

### 4.2 共享账户与余额

- 共享家庭账户允许双方代记，消费只影响实际选择的付款账户一次，不因记录人、付款人或同步而多扣一次。
- 本需求的“公开资产”指家庭内已共享账户；不公开私有账户，也不使另一半可选取小金库账户或读取其余额。
- 延续家庭／私有范围和已有互转外壳规则；选账户、搜索候选账、统计及导出均遵守现有范围。
- 双方可在各自手机看到并编辑同步后的同一账单，更新沿用既有冲突合并机制。
- 原有成员筛选需明确标注“付款人／记录人／为谁”口径；不得只改标题却继续按记录人计算付款额。
- 一期不增加银行自动扣款、读取另一半银行数据等能力，所有代记是账本记录。

## 5. 疑似重复账单提醒

### 5.1 保存前检查

- 一期针对家庭普通消费新增操作；优先比较相同付款账户、相同金额、接近的消费发生时间。金额按整数分精确比较。
- 可参考付款人、分类、备注中的商户信息辅助排序；现有无结构化商户字段时不承诺商户自动识别，不要求为提醒新增商户采集。
- 以消费发生时间比较，不以录入时间比较；补记也应检查。缺少小时分钟的记录降低匹配强度，不自动补零点后宣称精确匹配。
- 实现默认建议：双方均有明确时分时，以前后 10 分钟为强提示候选窗口；只有日期时，以同日候选作弱提示。此阈值是可调实现参数，不是用户已明确指定的业务规则。
- 不同付款账户、不同日期的同金额账不凭金额强提醒；排除当前正在编辑的账、已删除或已丢弃账，退款与转账不作为消费候选。
- 付款账户不明时，仅按可用信息给弱提示。提醒从不自动认定重复、不自动合并或删除。

### 5.2 提示文案与操作

强提示标题：**这笔消费可能已经记过了**

正文：家庭账本中有一笔金额相同、消费时间接近的记录，请确认是否为同一笔。

候选卡片展示：金额、消费日期和时间（若有）、一级／二级分类、付款人、付款账户、记录人、备注及关联行程。例如：

> ¥128.00 · 今天 12:36<br>
> 娱乐／聚餐 · 老婆付款 · 老婆的微信<br>
> 由你代记 · 杭州周末游

弱提示标题：**发现一笔相似账单**

弱提示正文：家庭账本中有一笔同日、同金额的记录，可查看是否为同一笔消费。

主要操作：**查看已有账单**。次要操作：**仍新增一笔**。支持返回继续编辑或取消新增。

- 查看已有账单不创建新账；可进入已有账单编辑并补充信息，退出后不自动保存原新增草稿。
- 仍新增一笔明确保存一个新的独立账单，即使信息相同也允许记录真实的两笔消费。
- 多条候选可供查看，不把第一条候选当作最终结论。
- 快速连点、重复提交同一保存请求，通过提交保护／操作幂等处理；这与两位成员分别创建的疑似同笔消费是两类问题。

### 5.3 离线与同步后发现

- 保存前仅能检查本机已经收到的家庭账；双方离线或尚未同步时，不能承诺提前发现对方的新账。
- 同一个流水 ID／同步操作重放属于技术去重，合并后只保留同一实体，不再次创建，不弹业务重复提醒。
- 双方分别创建两个流水 ID 的疑似同笔消费，同步后保留两条并提供可查看的疑似重复入口，等待用户核对；不得按金额时间自动删账。
- 用户认定重复后，显式选择保留哪条、删除哪条，展示受影响账户和金额并沿用正常删除及同步；不静默把两条拼接。
- 用户确认两条都是真实消费后，不反复提示同一组未变更候选。确认及忽略状态需能在家庭设备间保持一致。
- 修正前两条独立消费会按正常账参与余额与统计；界面不能宣称已自动去除重复。相关状态和处理过程需覆盖同步重试与并发。

## 6. 实现衔接与开发顺序

实现前已有账户所属成员、记录人、为谁、消费日期／可选时间、家庭同步及私有隔离。本轮新增独立付款人、行程实体／关联及重复确认实体，使用追加迁移 0005，备份格式升级为 v5。

1. **分类默认值与升级**：新账初始化、旧账整理预览及常用项衔接，先保证余额不变。
2. **付款人和代记**：补字段、默认联动、成员展示、统计／导出，再检查共享账户和编辑行为。
3. **行程**：家庭实体、单笔关联、本机当前行程、结束、汇总和导出，覆盖退款与历史补记。
4. **重复提醒**：本地候选检查和弹窗、离线同步后候选入口、显式保留／删除及忽略状态。
5. **整体验收**：升级与备份兼容、双设备离线／重放／冲突、行程与家庭总额核对、真机交互。

实现必须新增版本化数据库迁移，不修改既有迁移历史；家庭写入与 outbox 同事务，金额继续用整数分；修改同步、导出、备份及校验器时一起覆盖新增实体与字段。

历史记录人不可直接视为付款人。旧账可按账户归属给出可解释的推断，不能可靠确定的付款人保留“未确认”状态；不得把猜测显示为已知事实。统计须展示未确认部分，使分项与总额可核对。

本轮实现结果见第 9 节。下列清单保留为端到端验收标准；本机自动测试和隔离 Web 已覆盖主要规则，涉及真实同步服务和双 iPhone 的项目须完成真机验收后再勾选。
