# 开发决策

## 2026-10-29 · 首轮范围

- 三份原始材料作为需求参考；MD 与 PDF 均为 v0.3，内容一致。修订版准备文档中的未签名 IPA 路线优先于旧 EAS 描述。
- 首轮交付阶段 0 和阶段 1 的单机记账闭环，后续按阶段 2–6 推进。不把同步占位状态当成已同步，不填入示例贷款、房租或真实流水。
- 使用官方 SDK 57 模板的依赖版本：官方创建文档提示 SDK 58 过渡期真机 Expo Go 使用 SDK 57。以实际安装版本与 expo install --check 为准。来源：https://docs.expo.dev/get-started/create-a-project/
- create-expo-app 尝试写入沙箱外 ~/.expo 失败；改为读取官方 npm 模板并在当前目录初始化同等工程，不修改系统用户目录。
- 新项目固定 Bundle ID 为 `com.dwigh.familyledger`；以后升级保持不变，不添加扩展或小组件。
- SQLite 是唯一持久化来源；Zustand 只存筛选、主题等界面状态。家庭实体变更与 outbox 使用同一 SQLite 事务，偏好仅写本机。
- 金额以安全整数分表示；输入与显示均通过字符串转换，不使用浮点金额计算。
- 第一阶段仅本机成员“我”。“为谁”可选我、另一半、共同；后续配对才产生真实的第二成员。
- 标准模式按分类最近使用排序；自定义顺序以排序字段保存。先提供可访问的上移/下移按钮，拖动手势留作后续交互增强。
- 坚果云作为后续同步的建议默认值；不创建云账号、不上传数据、不索要密码。贷款还款默认不计支出；跨界转账按文档金额外壳方案，均待相应阶段实现。
- 正式上机前必须完成完整备份/恢复；本阶段是开发预览，暂不触发 iOS 云端打包。
- 网页预览由 `npm run web` 先导出再用本机静态服务器启动，显式发送 COOP/COEP 头。SDK 57 的 Metro 根 HTML 响应未经过 `enhanceMiddleware`，直接打开 Metro 网页缺少 SQLite 所需的隔离头。
- 实测发现 expo-sqlite 57.0.4 的 Web 同步桥把 Uint32 长度写入 Uint8Array，超过 255 字节时截断，导致默认分类等查询 JSON 损坏。通过可复现的 postinstall 脚本仅修复这一行长度编码；不修改 Expo Go 的原生 SQLite。后续升级 SDK 时必须重新审查。数据库先异步打开，避免首次 Worker 初始化时同步等待超时。
- 首次阶段 0/1 在同一轮建立，使用一次合并里程碑提交；后续阶段独立提交。排序先提供上移/下移，拖动交互待补充。
