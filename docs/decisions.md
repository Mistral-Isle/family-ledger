# 开发决策

## 2026-10-29 · 首轮范围

- 三份原始材料作为需求参考；MD 与 PDF 均为 v0.3，内容一致。修订版准备文档中的未签名 IPA 路线优先于旧 EAS 描述。
- 首轮交付阶段 0 和阶段 1 的单机记账闭环，后续按阶段 2–6 推进。不把同步占位状态当成已同步，不填入示例贷款、房租或真实流水。
- 使用官方 SDK 57 模板的依赖版本：官方创建文档提示 SDK 58 过渡期真机 Expo Go 使用 SDK 57。以实际安装版本与 expo install --check 为准。来源：https://docs.expo.dev/get-started/create-a-project/
- create-expo-app 尝试写入沙箱外 ~/.expo 失败；改为读取官方 npm 模板并在当前目录初始化同等工程，不修改系统用户目录。
- 新项目固定 Bundle ID 为 `com.dwigh.familyledger`；以后升级保持不变，不添加扩展或小组件。
- SQLite 是唯一持久化来源；Zustand 只存筛选、主题等界面状态。家庭实体变更与 outbox 使用同一 SQLite 事务，偏好仅写本机。
- 金额以安全整数分表示；输入与显示均通过字符串转换，不使用浮点金额计算。
- 第一阶段仅本机成员“我”。“为谁”可选我、另一半、共同；后续配对才产生真实的第二成员。
- 标准模式按分类最近使用排序；自定义顺序以排序字段保存。先提供可访问的上移/下移按钮，拖动手势留作后续交互增强。
- 坚果云作为后续同步的建议默认值；不创建云账号、不上传数据、不索要密码。贷款还款默认不计支出；跨界转账按文档金额外壳方案，均待相应阶段实现。
- 正式上机前必须完成完整备份/恢复；本阶段是开发预览，暂不触发 iOS 云端打包。
- 网页预览由 `npm run web` 先导出再用本机静态服务器启动，显式发送 COOP/COEP 头。SDK 57 的 Metro 根 HTML 响应未经过 `enhanceMiddleware`，直接打开 Metro 网页缺少 SQLite 所需的隔离头。
- 实测发现 expo-sqlite 57.0.4 的 Web 同步桥把 Uint32 长度写入 Uint8Array，超过 255 字节时截断，导致默认分类等查询 JSON 损坏。通过可复现的 postinstall 脚本仅修复这一行长度编码；不修改 Expo Go 的原生 SQLite。后续升级 SDK 时必须重新审查。数据库先异步打开，避免首次 Worker 初始化时同步等待超时。
- 首次阶段 0/1 在同一轮建立，使用一次合并里程碑提交；后续阶段独立提交。排序先提供上移/下移，拖动交互待补充。


## 2026-10-30 · D1 完整备份

- 按用户指定 PDF 第 12 节继续阶段 2，本轮实现 D1，不将尚未完成的 R1–R4 标为完成。
- 采用带格式版本的 JSON 全表备份，外层 SHA-256 用于检测意外损坏，不提供加密或来源认证。包含现有私有数据，界面明确告知，不上传云端。
- 当前恢复为整库替换，含 outbox、设备身份与时钟；恢复文件只用于单机灾难恢复，不作为配对或同步包。上线同步前必须补设备身份迁移策略。
- 限制 20 MB；字段与关系校验后事务恢复。保留数据库迁移元数据，由应用负责 schema；未来 schema、密钥存储变化必须升级备份格式，不能宣称支持未来所有数据。
- iOS 使用 Expo 配套 file-system、document-picker、sharing；Web 使用文件选择及下载。临时原生缓存分享／读取完成后清理。主题偏好由临时状态改为 SQLite 本机持久化。
- 阶段 2 仍未完成，因此尚未创建阶段完成提交；工作区保留上轮分类删除及本轮备份改动。

## 2026-10-30 · 阶段 2–5 连续实现与构建准备

- 用户确认坚果云和跨范围互转金额外壳。HTTPS 默认坚果云，可改用支持相同 WebDAV 方法的服务；不主动创建账号或上传真实数据。
- 家庭日志采用 XChaCha20-Poly1305（随机 24 字节 nonce、账本编号作为认证关联数据），钥匙串保存原生凭据。目录和文件元数据仍对服务端可见。先验证加密账本标识，再发布设备日志；`.tmp` + MOVE 后才确认上传。
- 本地写入保持 SQLite 事务；操作合并按 HLC 确定胜者，重复操作去重。预算是家庭实体；设备偏好、私有数据与恢复历史留在本机。贷款已还期数由初始基线和实际还款记录推导；分摊／押金整组并发以胜出计划版本保留对应流水，避免双重记账。
- 完整备份数据格式升级到 v3（计划与预算），兼容旧 v1/v2；外层完整性封装仍是 v1。恢复与同步互斥并清除当前连接配置，避免误传不同家庭数据；安全存储密钥不在数据库备份中。
- 家庭外壳可由双方编辑金额／日期或撤销，发起设备本地关联私有侧同步更新，备注与私有账户不进入外壳；关联墓碑保留以处理并发胜出变更。
- 分类删除常用项现在随接收分类迁移，丢弃时移除；恢复只在常用项尚未后来修改时还原。共享分类变更同步后本地处理私有记录，私有丢弃恢复入口受 VaultGate 保护。
- 统计页成员和“本金计支出”选项只影响本页报表与日历；预算和文件导出固定家庭口径、本金不计支出。贷款本金取导出范围截止日余额，贷款进度字段使用当前计划，不宣称历史贷款快照。
- SheetJS 使用官方 0.20.3 tarball；五工作表采用类型化金额与字符串，CSV 加 BOM 与公式注入保护。
- 通知采用本地调度，未配置 expo-notifications 的推送 entitlement 插件。最近 60 条提醒在北京时间上午 9 点；开启、启动、写入与同步刷新后更新。系统实际投递尚未验证。
- 已准备仅手动触发、contents:read 的 macOS 无签名 IPA 工作流，没有远程仓库和真机条件，尚未执行。代码检查点不是正式发布或全部阶段验收完成。

## 2026-10-30 · 参考图驱动的记账布局

- 用户希望基本记账信息集中在同一屏，并保留一级分类展开二级分类。采用分类区独立滚动、底部信息与键盘固定的结构；常用、分类管理、小金库、分摊、存常用与删除保留入口。
