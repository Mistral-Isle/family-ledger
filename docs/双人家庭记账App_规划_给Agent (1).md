# 双人家庭记账 iOS App · 需求与开发规划

<p class="meta">版本 v0.3 · 2026-10-29（新增分类管理与两种记账模式；简化车贷；押金与按月分摊） · 用途：交给编码 Agent 分阶段执行 · 技术路线：Expo (React Native) + 免费 Apple ID + SideStore 侧载</p>

## 0. 一页摘要

- **产品定位**：一个人能用的完整记账 App，加上"和另一半共用一本家庭账本"的能力；每月可导出家庭收支。
- **同步怎么做**：两部手机各存一份完整数据（离线可用），只把"家庭数据"的**加密操作日志**放到一个 WebDAV 文件夹里互相交换。存储端不运行任何代码，可以是**坚果云（推荐，随时可同步）**，也可以是**家里电脑**（只在家时同步）。打开 App、记完一笔都会自动同步，用户无感。
- **为什么不用 iCloud**：免费 Apple ID 签名的 App 不能使用 iCloud / CloudKit 和远程推送，所以同步方案必须绕开它们。
- **小金库**：独立的"私有范围"，有自己的账户和余额，数据只存本机、永不进入同步日志。从家庭账户转入小金库时，家庭侧只留一条"转出到个人"的外壳记录，保证两边余额一致。
- **常用卡**：记账页把 2–4 张置顶账户平铺成一行，点一下切换；默认选中"这个分类上次用的卡"。
- **分类管理**：分类可增删改、排序、隐藏。删除时三选一：迁移到已有分类、新建分类存放、丢弃记录。**三种方式都不改变任何账户余额**（丢弃的记录只是不再显示和统计，仍参与余额计算，还能恢复）。
- **两种记账模式**：标准模式（一级分类 → 展开二级）；日常模式（自己挑的常用项大卡片，可预设账户和金额，点一下就记完）。
- **贷款（简易版）**：只填 6 项（名称、每月还款、还款日、已还/总期数、剩余本金、扣款卡），不用填利率。可选"免息期"和"结清计划"：例如前 24 期免息，App 会算出"第 24 期还完后需要一次结清多少钱"、倒计时并提前提醒。全部只用加减法。
- **押金**：押金是"冻结的钱"，从银行卡转到押金账户，不算支出、仍算资产；退租时退回，被扣的部分才记为支出。
- **按月分摊**：一次付 3 个月房租，银行卡当天扣全额，但支出自动分成 3 笔落在 3 个月的时间线上，月度统计和预算不会失真。保险年费、会员年费也能用。
- **开发顺序**：骨架 → 单机记账 → 统计导出 → 小金库 → 贷款与租房 → 同步 → 打包上机。数据模型从第一天就按"可同步"设计。
- **准备文档里有一处会卡住**：EAS 云打包需要付费开发者账号来签名，免费 Apple ID 走不通。建议改用 GitHub Actions 的 macOS 机器出**未签名 ipa**，再由 SideStore 用免费 Apple ID 签名安装（详见附录 A）。

## 1. 目标与范围

### 1.1 目标

1. 日常记账体验不输现在用的 App，并且**记一笔更快**（常用卡平铺、分类按最近使用排序）。
2. 两个人各用自己的 iPhone 记账，数据自动汇总成一本家庭账本。
3. 每人有一个只自己可见的小金库。
4. 用最少的信息管理汽车贷款：还了多少、还剩多少、免息期结束前要准备多少钱结清。
5. 记录租房押金（冻结资金）与"押一付三"这类一次付多月的费用，按月分摊。
6. 每月导出家庭收支（Excel / CSV）。

### 1.2 本期不做（避免范围膨胀）
报销、存钱计划、多币种、拍票据识别、自动读取银行通知（iOS 不允许）、上架 App Store、Android 版、桌面小组件（会额外占用免费账号的 App ID 配额，见 §3）。

## 3. 关键约束（来自"免费 Apple ID + 侧载"这条路线）

这些约束直接决定了设计，Agent 必须遵守：

| 约束 | 影响 | 应对 |
|---|---|---|
| 免费账号不支持 iCloud / CloudKit 与远程推送 | 不能用 Apple 自家同步；对方记账后无法推送通知 | 用 WebDAV 文件交换同步；只用**本地通知**做还款提醒 |
| 签名 7 天有效，靠 SideStore 每天自动续签 | 过期后 App 打不开（数据还在） | 准备文档已有每日自动续签的快捷指令 |
| 同时只能有 3 个侧载 App 处于激活（SideStore 自己占 1 个） | 余量很少 | 不做小组件 / 扩展，保持单一 App |
| 每 7 天最多注册 10 个 App ID | 频繁改 Bundle ID 会被限 | Bundle ID 一次定好不再改（如 `com.<你的名字>.familyledger`） |
| 删除 App = 数据全丢 | 侧载 App 的风险点 | 必须先完成备份/恢复（D1），同步后对方手机也是一份备份 |
| 开发期用 Expo Go 预览 | 只能用 Expo Go 自带的原生库 | 选型只用 Expo Go 内置或纯 JS 的库；需要别的原生库时先停下来问 |
| Expo Go 里 Face ID 不可用 | 小金库解锁在 Expo Go 中会退化为设备密码 | 属正常现象；正式安装包里需在 `app.json` 配置 `NSFaceIDUsageDescription` |
| iOS 不保证后台运行 | 不能指望后台定时同步 | 前台触发同步：打开 / 回到前台 / 记账后 / 下拉 |

## 5. 同步方案（核心）

### 5.1 方案对比

| 方案 | 什么时候能同步 | 需要什么 | 评价 |
|---|---|---|---|
| A. 坚果云 WebDAV | 任何时候有网 | 一个坚果云账号（免费版额度远超记账需求） | **推荐**：真正无感，不依赖家里电脑开机 |
| B. 家里电脑开 WebDAV | 手机在家连 Wi-Fi 且电脑开着 | 电脑装 rclone，固定局域网 IP | 你最初的想法，可行但同步不及时；适合作为备选或备份 |
| C. 两台手机直连 | 两人同时打开 App 且在同一网络 | 需要额外原生库 | 不推荐 |
| D. 手动同步包 | 任何时候 | 微信 / AirDrop | 作为兜底，与 A/B 共用同一文件格式 |

**建议组合**：A 为主；如果想在家里电脑留一份备份，在电脑上装坚果云客户端同步同一个文件夹即可，电脑上就自动有全部（加密的）同步文件。B 保留为可选配置，App 里只是填一个不同的地址。

### 5.2 同步协议

**核心思想**：不同步"数据库文件"，而是同步"发生了什么"（操作日志）。每台设备只往自己的目录追加文件，存储端永远不会出现两人同时改同一个文件的冲突。

<figure><img src="figs/fig2-sync-flow.svg"/><figcaption>图 2 · 存储端目录结构与一轮同步的四个步骤</figcaption></figure>

1. **操作（op）**：每次对家庭数据的新增/修改/删除，在同一个 SQLite 事务里写入本地 `outbox` 表：
   `{opId, deviceId, seq, hlc, entity, entityId, action: "upsert"|"delete", record}`，`record` 为整条记录的最新内容。

2. **HLC（混合逻辑时钟）**：每个 op 带一个由"物理时间 + 计数器 + 设备 ID"组成的时间戳，即使两台手机时钟有偏差也能排出一致的先后。
3. **合并规则**：以记录为单位"后写者胜"（比较 HLC，相同则比 deviceId）。删除写为墓碑（`deleted=1`），不物理删除。两个人极少同时改同一笔账，记录级冲突处理足够；被覆盖时在同步日志里留一条记录，设置页可查看。
4. **余额不存储**：账户余额永远由"初始余额 + 流水"实时计算，因此不存在"两边余额对不上"的同步冲突。
5. **文件格式**：一批 op → JSON → （可选 gzip）→ XChaCha20-Poly1305 加密 → 文件名 `<起始seq>-<结束seq>.ops`（6 位补零）。先以 `.tmp` 上传，成功后 MOVE 改名。
6. **游标**：本地 `sync_cursor(deviceId, lastSeq)` 记录每个对方设备已合并到哪里；合并是幂等的，重复下载不会出错。
7. **首次开启同步**：把本机已有的全部家庭数据生成一次 upsert op，作为初始数据上传。

### 5.3 配对与加密

- 创建家庭账本时生成 32 字节随机**家庭密钥**和 `ledgerId`，存入 expo-secure-store。
- 配对二维码内容：`ledgerId`、家庭密钥、成员身份（"她"）、存储地址与凭据。**只在两人当面时展示**，页面上提示"请勿截图外传"。
- 对方扫码后生成自己的 `deviceId`，下载全部日志即完成加入。
- 设置页提供"家庭恢复码"（家庭密钥的可读编码），重装后输入恢复码 + 存储配置即可找回家庭数据。

### 5.4 什么时候同步（"无感"的实现）
打开 App、回到前台、保存一笔后 3 秒（防抖）、下拉刷新、前台停留时每 60 秒一次。离线时排队，下次联网补传。顶部用一个小云朵图标显示状态，不弹窗打扰。

### 5.5 两种存储端怎么配置
**坚果云**：网页端「账户信息 → 安全选项 → 第三方应用管理」生成**应用密码**；地址 `https://dav.jianguoyun.com/dav/`；App 里填账号 + 应用密码。两人用同一个坚果云账号即可（凭据通过配对二维码传给对方）。

**家里电脑（Windows）**：
```
rclone serve webdav D:\FamilyLedgerSync --addr 0.0.0.0:8080 --user ledger --pass <自定密码>
```

- 路由器里给电脑分配固定 IP（如 192.168.1.10），App 里填 `http://192.168.1.10:8080/`。
- 正式安装包需在 `app.json` 的 `ios.infoPlist` 中加入 `NSLocalNetworkUsageDescription`，以及 `NSAppTransportSecurity → NSAllowsLocalNetworking: true`（允许局域网 http）。
- Windows 防火墙放行 8080 端口；可用"任务计划程序"开机自启。

### 5.6 异常处理要求
网络失败、401（密码错）、507（空间满）、解密失败（密钥不匹配）分别给出中文提示；任何同步错误都不能阻止本地记账；同步过程不阻塞界面。

## 6. 小金库

<figure><img src="figs/fig3-vault.svg"/><figcaption>图 3 · 家庭范围与小金库的边界</figcaption></figure>

### 6.1 规则

1. 每个账户、流水、贷款都有 `scope` 字段：`family`（家庭，会同步）或 `private`（小金库，只在本机）。
2. **小金库流水只能使用小金库账户；家庭流水只能使用家庭账户**。在数据层做校验，界面上切换开关时账户条自动只显示对应范围的账户。
3. 写入 `outbox` 的唯一入口里断言 `scope === 'family'`，并为此写单元测试：任何 private 数据出现在 outbox / 导出文件中都算测试失败。
4. 家庭统计、家庭导出、家庭总资产全部排除 private；"我的"页面单独显示小金库余额与流水。
5. 我的个人统计可勾选"包含小金库"。

### 6.2 记账体验
记账页右上角"🔒 小金库"开关；打开后页面主色变为琥珀色，避免误记。小金库入口在"我的"页，需 Face ID / 设备密码解锁。

### 6.3 跨界转账（需要你确认，见 §14 问题 2）
从家庭账户（如工行 5617）转 500 元到小金库：

- **建议做法**：一次操作生成两条记录——家庭侧一条"转出到个人 −500"（只有金额，没有去向和备注，对方能看到），小金库侧一条完整的转入记录。这样工行卡余额在两台手机上一致。
- 如果连金额都不想让对方看到，唯一办法是从一开始就不让这笔钱经过家庭账户（例如单独一张只放在小金库里的卡），否则家庭账户余额两边必然对不上。

### 6.4 备份
小金库不参与同步，所以完整备份（D1）必须包含它；可选把小金库单独加密（用个人密码）上传到 WebDAV 的另一个目录。

## 7. 贷款（简易版）

<figure><img src="figs/fig5-loan.svg"/><figcaption>图 4 · 新建贷款只填 6 项；卡片上直接看到结清要准备多少钱（示例数字）</figcaption></figure>

### 7.1 只记你关心的
你的情况：贷款 5 年（60 期），前 2 年（24 期）免息，打算第 24 期还完后一次结清，避开后 3 年的利息。所以 App 只需要知道"每月还多少、还剩多少、哪天之前结清、到时要准备多少钱"。

- **必填 6 项**：名称、每月还款额、每月还款日、已还期数 / 总期数、当前剩余本金、扣款账户。
- **可选 2 项**：免息期数、结清计划（默认"免息期最后一期后"）。
- 已经还了一段时间也没关系：直接填进度和剩余本金，不需要补录以前的还款，系统记一条"期初"标记即可。
- 不需要利率、贷款机构、等额本息之类的信息。

### 7.2 计算（只有加减法）

- 每记一期还款：剩余本金 −= 本期本金。免息期内本期本金 = 整笔月供；免息期后 = 月供 − 用户填的利息（没填按 0）。
- 结清金额 = 当前剩余本金 − （计划结清期 − 已还期数）× 月供。
- 结清截止日 = 下次还款日 +（计划结清期 − 已还期数 − 1）个月。
- 校准：用户输入银行显示的剩余本金，差额生成一条"调整"记录（不算支出），之后都以新数字为准。

**单元测试期望值**（示例：10 万、60 期、前 24 期免息、月供 1,666.67、每月 15 日还款，2026-10-29 时已还 14 期）：剩余本金 76,666.62；免息还剩 10 期；结清截止 2027-08-15；结清金额 59,999.92；倒计时 290 天。

### 7.3 记账口径

- 每期还款是一条"还款"记录：扣款卡 → 贷款账户（流转）。免息期内整笔都是本金，**不产生支出**；有利息时利息部分记为支出（汽车 / 贷款利息）。
- 结清同理；违约金 / 手续费记为支出。
- 统计里提供开关"贷款还款计入支出"，默认值见 §14 问题 4。
- 首页在还款日前 3 天出现提醒卡片，点一下预填金额和扣款卡；结清截止日前 30 天、7 天再各提醒一次（本地通知）。
- 结清后贷款归档，历史记录保留。

## 8. 押金与按月分摊（租房）

<figure><img src="figs/fig7-rent.svg"/><figcaption>图 5 · 押一付三：押金冻结，3 个月房租分别落到 3 个月的时间线上</figcaption></figure>

### 8.1 押金

- 新账户类型 `deposit`，在资产页"冻结资金"分组显示。付押金 = 付款账户 → 押金账户的转账，不算支出，但仍算你的资产。
- 退押金：选退回账户、填实际退回金额；没退回的差额自动生成一条支出（默认分类"房租 / 押金扣除"，可改）；押金账户归零并归档。
- "可用余额" = 普通账户合计，不含押金和预付费用。
- 通用：门禁卡押金、设备押金、停车卡押金都能这样记。

### 8.2 按月分摊

- 记支出时打开"分摊"开关：选月数 N、起始月份（默认本月）、每月日期（默认与付款日相同）。
- 保存时生成：1 条付款记录（付款账户 → 系统账户"预付费用"，显示为"房租 · 3 个月"）+ N 条支出（从"预付费用"扣，分类如"固定 / 房租"，日期分别是每个月的对应日，金额均分，尾差放在最后一期，标注 k/N）。这些记录共用一个 `split_group_id`。
- 未来日期的分摊支出属于各自的月份，只在那个月的统计和预算里出现。
- 修改或删除时按整组处理：改金额或月数后整组重新拆分。
- 这些都是普通家庭流水，会正常同步。保险年费、会员年费等也可以用。

### 8.3 租房快捷设置（P1）
填 5 项：月租、押几（默认 1）、付几（默认 3）、起租日、付款卡。App 一次生成：押金（押几 × 月租）、首次付款并按月分摊（付几 × 月租，分付几个月）、下次交租提醒（起租日 + 付几个月，提前 7 天）。之后每次交租点提醒即可，金额和分摊都已预填。退租时一键进入退押金流程。

**单元测试期望值**（示例：月租 3,000，押一付三，起租 2026-11-01，工行 5617 付款）：工行当天 −12,000；押金账户 3,000；2026-11-01、12-01、2027-01-01 各一笔房租支出 3,000；11 月底预付费用余额 6,000，1 月起为 0；下次交租 2027-02-01，2027-01-25 提醒。另测尾差：10,000 分 3 个月 → 3,333.33 / 3,333.33 / 3,333.34。

## 9. 分类管理与记账模式

<figure><img src="figs/fig8-category.svg"/><figcaption>图 6 · 标准模式、日常模式与删除分类对话框（示意）</figcaption></figure>

### 9.1 增、改、排序、隐藏

- 入口：设置 › 分类管理（支出 / 收入两个页签）；记账页长按某个分类也能直接编辑。
- 一级分类下面没有二级时，一级本身可直接选；以后给它加了二级，原来记在一级上的记录在统计里显示为"某某（未细分）"。
- 二级分类可以整体移到另一个一级下，记录跟着走，不需要迁移。
- 隐藏 ≠ 删除：隐藏后记账页看不到，历史数据完全不受影响，随时可取消隐藏。
- 至少保留一个支出分类和一个收入分类。

### 9.2 删除时的三种处理
| 方式 | 做了什么 | 为什么余额不变 |
|---|---|---|
| 迁移到已有分类 | 把这些记录的 `category_id` 改为目标分类 | 只改分类，金额、账户、日期都不动；余额由流水计算，自然不变 |
| 新建分类存放 | 先按用户填的名称/图标/所属一级新建分类，再同上迁移 | 同上 |
| 丢弃记录 | **不物理删除**，给记录打 `discarded=1`：明细、统计、预算、导出、搜索全部排除，余额计算照常包含 | 记录仍参与余额计算，所以当前余额和历史任意一天的余额都不变 |

补充规则：

- 只有支出、收入、退款带分类；转账、还款、押金、分摊付款不受影响。退款跟随它对应的原支出一起处理。
- 删除一级分类时先问：①把它的二级分类挪到别的一级下（数据跟着二级走），然后删除空的一级；或 ②对下面所有记录统一迁移 / 新建 / 丢弃。
- 删除前显示"N 笔 · 合计 ¥X · 涉及 YYYY-MM 至 YYYY-MM"，确认后才执行；整个过程在一个数据库事务里完成。
- 小金库里用到该分类的记录在本机按同样方式处理。
- 日常模式里指向被删分类的常用项：迁移时自动改指向新分类；丢弃时这个常用项一起移除。
- "丢弃"了的记录可在设置 › 已丢弃记录里恢复。

### 9.3 和同步的配合

- 分类删除作为一个操作同步，内容包括处理方式和目标（`merged_into` 指向目标分类，或标记为丢弃）。
- 每台手机收到后在本地执行同样的处理，包括自己小金库里的记录。
- 以后再收到引用已删分类的记录（例如对方离线时记的），合并时自动改到 `merged_into`，或标为丢弃。规则幂等，重复执行结果一样。

### 9.4 两种记账模式

- **标准模式**：一级分类网格；点一个一级，在原地展开它的二级（不跳新页面）；选好二级后输入金额。适合不常记的类型。
- **日常模式**：显示"我的常用"大卡片，每张 = 一个分类 + 可选预设（显示名、账户、金额、备注）。点一下带出全部预设：金额也预设了的话直接点"完成"，一步记完；没预设金额就把光标停在金额上。最后始终有一张"全部分类"，点开就是标准模式的分类选择。
- 记账页顶部"标准 / 日常"切换并记住上次选择；设置里可选打开记账页时默认用哪个。
- 添加常用项：日常模式里点"＋ 添加常用"，或在明细里长按某笔记录选"存为常用"（自动带上它的分类、账户、金额）。
- 常用项存在 `local_pref`，每台手机各一套：你的"早餐"和她的"早餐"可以是不同的卡和金额。
- 打开小金库开关时，常用项里预设的家庭账户不能用，自动换成小金库默认账户。

**单元测试要求**：造 3 个账户、跨 3 个月共 50 笔记录；分别执行三种删除方式后，断言每个账户的当前余额和每个月末余额与删除前**完全相等**；迁移后目标分类的统计金额增加相应数额；丢弃的记录不出现在统计和导出中；恢复后统计回到删除前。

## 13. 给 Agent 的执行约定

1. **金额全部用整数分**，显示时再格式化；任何计算不得出现浮点金额。
2. 所有 ID 用 UUID；所有家庭数据写操作必须经过同一个 repository 层，在同一事务内写 outbox。
3. 只使用 Expo Go 可运行的库；需要其它原生库时**先停下来说明原因并询问**。
4. 每个阶段结束：运行测试、更新 `README` 的"已完成功能"、单独提交一次 git commit。
5. 界面文字集中放在 `src/i18n/zh.ts`，不要散落在组件中。
6. 不要修改 Bundle ID；不要添加 App Extension / 小组件。
7. 同步、贷款与分摊计算、小金库校验、分类删除（余额不变）这几块必须有单元测试，且测试先于界面完成。
8. 遇到需求不明确的地方，按本文档"建议做法"实现，并在 `docs/decisions.md` 记一笔。

## 14. 需要你确认的问题

1. **同步存储**：用坚果云（推荐），还是家里电脑，还是两者都配？
2. **小金库转账**：家庭侧显示"转出到个人 −金额"可以接受吗？
3. **车贷信息**：只需要 6 个数：每月还款额、还款日、已还期数、总期数（60）、当前剩余本金、扣款卡；再加免息期数（24）。另外请看一眼合同：**免息期内提前结清收不收违约金或手续费**？
4. **车贷算不算支出**：免息期内月供全是本金，按会计口径不算支出，只在"流转 / 还款"里显示。你希望每月支出统计里**包含**月供（更贴近"这个月花了多少钱"的感觉），还是**不包含**（更准确）？默认我按"不包含"写，统计页可以随时切换。
5. **租房信息**：月租多少、起租日（或上次交租日）、押金多少、用哪张卡付？现在这期房租是不是已经交过了（交过的话录入时选"已付到几月"）？
6. **另一半的手机**：她也要按准备文档走一遍 SideStore 流程（用她自己的 Apple ID、也需要外区账号下载 LocalDevVPN、每天自动续签），可以接受吗？如果嫌麻烦，可以考虑付费开发者账号（国内约 ¥688/年）：签名一年有效、能用 TestFlight，也能直接用 iCloud 同步——但本方案不依赖它。
7. **历史数据**：现在的 App 能导出 CSV 吗？需要导入吗？
8. **日常模式**：我理解的"常用项"是"分类 + 可选的预设账户和金额"（例如"早餐 · 工行卡 · ¥7"点一下就记完）。如果你想要的只是"把常用的几个分类放在一页"、不需要预设，也可以，告诉我即可。
